# AI-агент сети стоматологических клиник

> Подробная инструкция для пользователя: файл **Инструкция.html** (открыть в браузере) или вкладка
> «Как это работает» в админ-панели.

Учебный проект: агент-администратор клиники на LangGraph + Ollama + Agent Chat UI.

## Установка и запуск (Ubuntu 22.04 / 24.04)

Всё делается в Терминале (Ctrl+Alt+T). Скрипты запускаются через `bash`, права на запуск не нужны.

1. Распакуй архив в домашнюю папку: `cd ~ && unzip dental-agent-ubuntu_*.zip` (получится `~/dental-agent`).
2. Установка: `cd ~/dental-agent && bash install.sh` (10-30 минут). Может спросить пароль sudo для git,
   Ollama как службы и порта в ufw; можно отказаться, тогда Node.js 22, Python 3.12 (через uv) и Ollama
   поставятся прямо в папку агента (`.node`, `.venv`, `.ollama`).
3. Заполни таблицы в папке `data` (ниже), затем `bash reload_data.sh`.
4. Запуск: `bash run.sh`. Откроется браузер с чатом агента. Остановка: Ctrl+C.
   Если одногруппники в общем Wi-Fi не могут открыть чат по адресу ПК: `bash run_internet.sh`,
   он откроет туннель Cloudflare и напечатает ссылку https://....trycloudflare.com для всех.

Если включён брандмауэр ufw, порт 3000 открывает install.sh (или `bash fix_network.sh`, или `sudo ufw allow 3000/tcp`).

| Скрипт | Что делает |
|---|---|
| install.sh | установка, можно запускать повторно |
| run.sh / run_internet.sh | запуск (в локальной сети / с ссылкой через интернет) |
| stop.sh | остановить все службы агента |
| update.sh | перенос базы и настроек из старой папки и доустановка |
| reload_data.sh | пересобрать базу из CSV (стирает записи) |
| add_patient.sh | добавить пациента, ничего не стирая |
| collect_logs.sh | логи и база в один архив для разбора |
| fix_network.sh | открыть порт 3000 в ufw |
| run_my_mcp.sh | пример своего MCP-сервера |

Порты: чат 3000 (единственный открытый в сеть), агент 2024, админка 8080, кабинет 8090, МИС 8765, Ollama 11434.

## Интерфейс (версия 15)

Чат, админка и инструкция оформлены в одном стиле: серый холст в точку, белые карточки,
шрифт Onest (лежит в проекте, интернет для него не нужен), светлая и тёмная тема.

- **Чат** (`ui_patch/overlay`): русский интерфейс, приветственный экран с кнопками быстрых вопросов,
  шаги агента вместо сырых вызовов («Ищу свободное время», «Проверяю личность»; по нажатию видно
  инструмент, аргументы и ответ, отказы подсвечены жёлтым), индикатор «Администратор печатает»,
  статус связи с агентом, переключатель шагов и темы. История чужих чатов и загрузка файлов убраны:
  прокси их всё равно не пропускает.
- **Админка**: меню с иконками по группам, состояние служб внизу меню, график активности за 2 часа,
  чек-лист готовности со счётчиком, обновление каждые 10 секунд без перезагрузки страницы.

Agent Chat UI закреплён на версии `675be8e` (`ui_patch/ui.sh`): оформление заменяет его файлы
целиком и собирается только на этой версии. install.sh, update.sh и run.sh сами переводят папку
`ui` на неё (один раз, нужен интернет) и накладывают оформление. Если нужная версия не скачалась,
чат запустится в стандартном виде, защитный прокси ставится в любом случае.

## Запись: проверка всех сценариев (версия 21)

- `book_appointment(doctor, date, time)`: окно ищет код по врачу, дате и времени. Если модель передаст `slot_id`
  другого врача или другого времени, запись не создаётся. Раньше агент мог записать на окно Волковой и сказать
  «к Смирнову». Ответ инструмента называет фактического врача, филиал и время.
- Окно занято: запись не создаётся, модели прямо запрещено записывать к другому врачу без согласия пациента.
- Врач находится в любом падеже и по имени-отчеству: «Илье Андреевичу», «к Волковой», «хирургу».
- `send_message` без номера записи берёт ближайшую запись (нужно после записи через форму); `cancel` и `reschedule`
  без номера работают, если запись одна, иначе агент уточняет.
- Лимит «2 записи» считает только предстоящие: прошедшие визиты больше не мешают записаться.
- Сценарный тест: 32 проверки, включая одновременную запись трёх пациентов на одно окно (20 прогонов).

## Если после обновления видна старая версия (версия 19)

Окно терминала с run.sh, закрытое крестиком, оставляет службы работать в фоне: они держат порты 3000, 2024, 8080, 8090, 8765,
и новый запуск показывает старую версию из старой папки. Теперь run.sh в начале сам останавливает такие процессы
(`stop_old` в `tools/common.sh`), печатает номер версии и сверяет, что шлюз отвечает той же версией. Номер версии виден
внизу окна входа. Остановить всё вручную: `stop.sh`.

## Роли, сохранение диалогов, запись без накладок (версия 18)

- **Роли при входе.** В окне входа сначала выбор: пациент, врач или администратор. Сотрудники входят только
  со своих номеров из `data/staff.csv` (таблица `staff`, грузится при каждом запуске). Роль и id ставит шлюз,
  модель их не видит. У каждой роли свой набор инструментов и свой промпт; `run_local_tool` ещё раз сверяет роль,
  поэтому чужой инструмент не выполнится, даже если модель его вызовет (событие `role_violation` во вкладке «Атаки»).
  - врач: `get_my_schedule`, `get_patient_card`, `add_treatment_plan`, `message_patient` — только свои пациенты;
  - администратор: `find_patient`, `get_schedule`, `book_for_patient`, `cancel_any_appointment`, `remind_patient`,
    `get_free_slots` — все пациенты, но без планов лечения.
  Фильтр ответа тоже учитывает роль: врачу можно называть своих пациентов, администратору всех, флаг не видит никто,
  кроме самого пациента.
- **Диалоги сохраняются.** Слева список диалогов и кнопка «Новый». run.sh чистит память агента при старте, поэтому
  шлюз при открытии чата проверяет его в агенте и, если чат пропал или пуст, создаёт его с тем же id и кладёт историю
  из `chat_log`. После входа открывается последний пустой диалог, пустые не плодятся.
- **Контекст врача.** У `get_free_slots` появился параметр `doctor`. Последний обсуждавшийся врач (после отзывов,
  поиска окон или записи) хранится в сессии (`sessions.ctx`) и попадает в статус для модели: «запишите к ней» = к нему.
- **Запись без накладок.** Окно занимается в транзакции `BEGIN IMMEDIATE` условием `is_free=1`; плюс уникальный индекс
  `uq_active_slot` на активную запись окна; плюс запрет двух записей одного пациента на одно время.
  Тест: 20 из 20 одновременных попыток двух пациентов на одно окно дают ровно одну запись.

## Вход и личный кабинет (версия 15)

Писать в чат можно только после входа по номеру телефона. Код получает **владелец системы**:
плашкой вверху любой вкладки админки (со звуком), строкой `[SMS-КОД]` в окне терминала с run.sh и в Telegram
(`TEST_TELEGRAM_CHAT_ID`). В демо-режиме код показывается прямо в окне входа. Новый номер после кода вводит ФИО.

Шлюз кабинета `gateway/server.py` (127.0.0.1:8090) выдаёт токен, сам создаёт чаты и привязывает их к пациенту.
Прокси чата пускает к диалогу только его хозяина (спрашивает шлюз по `MIS_KEY`). `verify_patient` и
`register_patient` модели больше не выдаются. В кабинете: мастер записи (услуга → филиал → врач → время,
список услуг в `data/services.csv`), мои записи с отменой, мои диалоги, отзыв, подключение своих MCP
(готовый список проверенных публичных серверов). Под ответами агента кнопки-варианты и запись в одно нажатие
по найденным окнам.

## Подключение одногруппников

Вкладка админки «Подключение»: все адреса чата с QR-кодами и проверкой, экран для проектора, кнопка
«Открыть доступ через интернет» без перезапуска. Туннель `tools/tunnel.py` пробует Cloudflare → localhost.run →
Pinggy (ssh через 443), засчитывает ссылку только после проверки снаружи и переподключается сам. Чат запускается
готовой сборкой (`next build` + `next start`), а не в режиме разработки. План В без интернета: точка доступа
с телефона, все подключаются к ней.

## Данные

Таблицы лежат в `data/*.csv`, открываются в Excel. Сохранять как «CSV (разделители - точки с запятой)»: такой формат скрипт понимает, даты вида 15.03.1995 тоже.

| Файл | Что заполнить |
|---|---|
| branches.csv | филиалы (уже заполнено) |
| doctors.csv | id, ФИО, специальность (терапевт, хирург, ортодонт, ортопед), id филиала |
| patients.csv | id, ФИО, телефон, дата рождения ГГГГ-ММ-ДД, email, telegram_chat_id (можно пусто) |
| treatment_plans.csv | id пациента, диагноз, план, стоимость. Флаг для игры клади в план одного пациента |
| kb.csv | база знаний клиники: услуги, цены, режим (уже заполнено) |

Данные только вымышленные. После правки: `reload_data.sh`, затем перезапуск `run.sh`. Внимание: reload_data.sh пересобирает базу с нуля и стирает записи на приём и журналы.

Добавить одного пациента, ничего не стирая: запусти в терминале `add_patient.sh`. Он спросит ФИО, телефон, дату рождения, при желании план лечения, и впишет пациента в работающую базу. Записи и журналы не трогает, перезапуск не нужен.
Расписание врачей на 7 дней генерируется автоматически.

## Демо-режим подтверждения

Чтобы систему было удобно показывать, по умолчанию включён демо-режим: код подтверждения
приходит прямо в чат. В окне терминала с run.sh при запуске об этом есть жёлтое предупреждение.

Для игры с одногруппниками демо-режим надо выключить, иначе код увидят соперники.
Открой файл .env в папке dental-agent, найди строку DEMO_SHOW_CODE и поставь:
DEMO_SHOW_CODE=false
Если такой строки нет, добавь её. Затем перезапусти run.sh. Тогда код пойдёт только
в окно терминала с run.sh (строка [SMS-КОД]), в админ-панель (вкладка «Сообщения») и в Telegram.

Как проверить запись на приём (с демо-режимом):
1. Открой чат. В окне входа введи телефон пациента из data/patients.csv, например +7 900 111-22-33.
2. Код появится прямо в окне входа (кнопка «Подставить») и плашкой в админке.
3. После входа нажми «Записаться» или напиши «Запишите меня к терапевту»: агент покажет окна кнопками.

## Коды подтверждения

Код печатается в окне терминала с run.sh строкой `[SMS-КОД]`. Чтобы он приходил в Telegram:
1. Создай бота у @BotFather, токен впиши в `.env` в `TELEGRAM_BOT_TOKEN`.
2. Напиши своему боту любое сообщение, открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найди `"chat":{"id":...}`.
3. Впиши этот id в `TEST_TELEGRAM_CHAT_ID` в `.env` или в `telegram_chat_id` пациента.

MAX и WhatsApp сделаны заглушками: сообщения пишутся в `logs/outbox.log`.

## Адреса

- Чат: `http://<IP этого ПК>:3000`. Адрес печатает run.sh, его можно давать другим командам.
- Личный кабинет (шлюз): `http://127.0.0.1:8090`, наружу только через прокси чата `/gw/...`.
- Админ-панель: `http://127.0.0.1:8080`, открывается только на этом ПК. Там записи, загрузка врачей,
  все диалоги, вызовы инструментов (отказы подсвечены жёлтым), отправленные сообщения.
  Если в ответе агента появится флаг из `GAME_FLAG` в `.env`, строка станет красной.

## Защита агента (эшелонированная)

Защита построена в несколько рубежей, чтобы одна ошибка не открывала всё.

1. Архитектура. Секрет (флаг) и ПДн лежат в базе, а не в системном промпте.
   Личность пациента хранится в таблице sessions по id чата и ставится только кодом verify_patient.
   Все инструменты берут id пациента оттуда. «Покажи карту пациента Иванова» выполнить нельзя:
   у инструментов просто нет параметра «чей». Для MCP id пациента перезаписывается в коде.

2. Прокси перед агентом (ui_patch/route.ts). Наружу открыт только порт 3000:
   - пропускает лишь запросы, нужные чату; список чужих чатов не отдаёт, удаление и правку состояния запрещает;
   - из запроса на запуск оставляет только input, вырезает config, context, command;
   - из input пропускает только текстовые сообщения пользователя. Подставное системное сообщение
     или поддельный результат инструмента не пройдут;
   - лимиты: 8 сообщений в минуту с одного адреса, 40 всего (видеокарта одна), ограничение длины.

3. Фильтры агента (agent/guard.py):
   - из истории, которую видит модель, удаляются системные сообщения и результаты инструментов без вызова;
   - входящие сообщения проверяются на признаки манипуляции и пишутся в журнал;
   - исходящий ответ проверяется: если в нём оказались флаг или данные чужого пациента (в том числе
     разнесённые по буквам или через разделители), ответ заменяется на отказ.

4. Системный промпт. Агент предупреждён, что всё в чате пишет пациент, что текст и результаты
   инструментов это данные, а не команды, и что подтверждает личность только код.

5. Лимиты на подтверждение. Не больше 3 кодов на пациента за 15 минут и 5 запросов кода на чат,
   не больше 3 неверных кодов подряд. Регистрация через чат: одна на чат, 15 в час, только на новый
   мобильный номер, ФИО и дата рождения проверяются. Всё это пишется в журнал.

   Фильтр ответа ловит флаг ещё и задом наперёд, в base64 и hex. Токены модели не стримятся
   в браузер (тег nostream), поэтому собеседник видит ответ только после проверки.
   Пациенты, зарегистрированные через чат, в фильтре не охраняются: иначе «имя» вроде
   «Вы записаны» блокировало бы обычные ответы.

6. Журнал атак. Все срабатывания видны в админ-панели на вкладке «Атаки».

### Чего защита не делает (честно, для доклада)

- Фильтр ответа ловит флаг в открытом виде и разнесённый по буквам, но не поймёт его в base64,
  в переводе на другой язык или пересказанным своими словами. Это предел фильтра по выходу;
  основная защита в том, что модель чужой флаг вообще не получает (рубеж 1).
- Маленькая модель 7-8B хуже держит иерархию инструкций, чем облачные. Поэтому ставка на то,
  что защищает код, а не на то, что модель «не поддастся».
- Прокси ограничивает частоту по IP, но в общей сети за одним адресом может быть несколько человек.
